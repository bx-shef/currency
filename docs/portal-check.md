# Проверка на портале

Всё, что ниже рантайма Битрикса, тестами не закрыть: установка, права,
запись курсов ядром, агент, поведение при обновлении модуля. Проверять это
приходится руками — и лучше по списку, потому что забытый шаг находит не
разработчик, а клиент.

Процедура рассчитана на **отдельный стенд**, а не на боевой портал: она пишет
курсы валют, а по ним считаются сделки, счета и цены.

Раскладка репозитория — в [module-structure.md](module-structure.md), сборка —
в [build-and-install.md](build-and-install.md).

## Что понадобится

| | |
|---|---|
| портал | «коробка» Битрикс24 или БУС, главный модуль **22.600.300** и выше, модуль **«Валюты»** |
| PHP | **8.2** и выше, расширения `mbstring`, `simplexml` |
| кодировка | **только UTF-8** |
| линейка | `shef.options` **3.0.0**, `shef.problems` **2.0.0**, `shef.insync` **2.0.0** и выше, установлены |
| сеть | с сервера портала открыт `https://services.nbrb.by` |
| валюты | базовая — **BYN**; заведены USD, EUR, RUB |
| доступ | администратор портала, отдельный пользователь с правом «R» на «Валюты», доступ к файлам по ssh |
| архив | со страницы релиза либо собранный `./build.sh` |

Для сценария «обновление» нужен стенд, где уже стоит **1.x** — на нём
проверяется то, ради чего 2.0.0 сделана мажорной.

## Перед началом

Снимите копию курсов, настроек и агента — шаги пишут и удаляют:

```bash
mysqldump -u… portal b_catalog_currency_rate > /tmp/rates.before.sql
mysqldump -u… portal b_option --where="MODULE_ID='shef.currency'" > /tmp/opt.before.sql
mysqldump -u… portal b_agent --where="MODULE_ID='shef.currency'" > /tmp/agent.before.sql
mysqldump -u… portal b_module_to_module --where="TO_MODULE_ID='shef.currency'" > /tmp/events.before.sql
```

## A. Чистая установка

| # | шаг | ожидается |
|---|---|---|
| A1 | Распаковать архив в `bitrix/modules/`, «Установить» на странице модулей | «Модуль успешно установлен» |
| A2 | То же на стенде без `shef.insync` 2.0.0 | отказ со ссылкой на `shef.insync` и версией |
| A3 | Настройки модуля `/bitrix/admin/settings.php?mid=shef.currency` | вкладка «Общие»: «Базовая валюта проекта BYN», порог, коэффициент, строка агента |
| A4 | `/bitrix/admin/agent_list.php`, фильтр по модулю `shef.currency` | один агент `\Shef\Currency\Sync\Agent::process([]);`, **неактивен**, раз в сутки, сортировка 100 |
| A5 | На странице настроек включить агент | агент активен |
| A6 | Сменить базовую валюту на RUB, открыть настройки модуля | красная строка: сделать BYN базовой, базовая сейчас RUB. Вернуть BYN |

## B. Курсы

| # | шаг | ожидается |
|---|---|---|
| B1 | `/bitrix/admin/currencies_rates.php`, «[SH] Запросить курсы валют» → «На сегодня» | сообщение «Курсы НБ РБ получены и записаны»; у USD, EUR, RUB курс на сегодня, как на nbrb.by; у RUB — за 100 |
| B2 | Повторить B1 | те же записи обновлены, дублей нет |
| B3 | «На завтра» утром, до установки курсов банком | «Курсы НБ РБ не записаны…»; в журнале событий `NB RB: no rates on <завтра>`; курсы не тронуты |
| B4 | «На завтра» после установки курсов банком | курсы на завтра записаны |
| B5 | Коэффициент 1.02, B1 | курс USD = курс банка × 1.02, 4 знака |
| B6 | Коэффициент — стереть поле и сохранить, B1 | курс как у банка, **не ноль** |
| B7 | Порог 50, курс на сегодня удалить руками, B1 | курс не записан: сдвиг от вчерашнего меньше 50 % — действует вчерашний |
| B8 | Порог 0, B1 | курс записан |
| B9 | Выполнить агент из списка агентов | курсы на сегодня записаны, агент остался в списке |
| B10 | Формат даты сайта `MM/DD/YYYY`, B1 | курсы записаны на правильную дату |

## C. Права и защита

| # | шаг | ожидается |
