# Курсы НБ РБ: shef.currency

Модуль раз в сутки берёт курсы НБ РБ
(`https://services.nbrb.by/XmlExRates.aspx?ondate=m/d/Y`) и пишет их в
штатный модуль «Валюты» (`b_catalog_currency_rate`), а на странице курсов
`/bitrix/admin/currencies_rates.php` даёт кнопку «[SH] Запросить курсы валют»
— на сегодня и на завтра. Документация —
[README](https://github.com/bx-shef/currency/blob/main/README.md).

## Что пишется и когда

Правило одно, оно в `\Shef\Currency\Main\Rates::plan()`:

* для **каждой валюты портала**, которая есть в ответе НБ РБ, кроме базовой;
* значение — курс НБ РБ × коэффициент, округлённый до 4 знаков, за
  столько единиц, сколько у банка (`RATE_CNT` = `Scale`: рубли — за 100);
* порог сравнивает курс **за одну единицу** с действующим на портале — на
  эту дату, иначе с последним до неё. Меньше порога — курс не пишется,
  действует прежний. Курса нет вовсе — пишется всегда;
* курс на дату уже есть — обновляется, нет — добавляется.

Валюта, которой нет на портале, не пишется: чтобы появился курс юаня —
заведите валюту CNY в «Валютах», курс придёт следующим запуском.

## Настроить после установки

1. Базовая валюта портала — **BYN**. Иначе модуль не пишет ничего:
   `\Shef\Currency\Main\Utils::checkBaseCurrency()` возвращает ошибку, и на
   странице настроек об этом красная строка.
2. Настройки модуля (`/bitrix/admin/settings.php?mid=shef.currency`):
   * «Менять курс только при колебании не менее чем на %» — целое 0…100,
     опция `DEF_sizeChange`; 0 — писать всегда; сдвиг ровно на порог —
     пишется;
   * «Коэффициент» — от 1 до 400, опция `DEF_factor`; 1 — курс как есть.
     «На 2 % выше банка» — это 1.02. Ниже банковского курс не опустить.
   Испорченное значение (пусто, текст, вне границ) модуль читает как
   умолчание — 0 и 1, см. `\Shef\Currency\Main\Constants`.
3. Там же — строка агента: установщик ставит агент выключенным (нет его —
   поставит страница у того, кто может менять настройки модуля),
   **включить** его кнопкой. Первый запуск — в 00:20 ночи после установки,
   дальше раз в сутки. Включили позже — первый запуск на ближайшем хите,
   возможно несколько подряд, пока агент не догонит расписание (так ядро
   ведёт периодические агенты; на стенде не проверено).
4. У курсов в «Валютах» проверить **курс по умолчанию**: он действует там,
   где курса на дату нет.

## Курс не обновился — порядок разбора

1. **Журнал событий**, тип `SH_PROBLEMS_SYNC` («Проблема с
   синхронизацией»), источник `shef.currency` — там причина каждого сбоя:
   * `module.currency BYN !== b24.currency …` — базовая валюта не BYN;
   * `NB RB: no rates on <дата>` — у банка нет курсов на эту дату (завтра
     — до их установки банком). Замерено 2026-09-29: курсы на воскресенье
     сервис отдаёт, на 30-е вечером 29-го уже отдавал;
   * `status: …`, ошибки соединения — сервер НБ РБ не ответил или порталу
     закрыт выход наружу;
   * `NB RB: response is not XML` / `root element is not DailyExRates` —
     ответил не сервис курсов (прокси, заглушка провайдера);
   * `Error add|update rate <валюта>: …` — ядро отклонило запись, текст
     после двоеточия — от ядра.

   Сбой соединения попадает в журнал **дважды**: одну запись пишет клиент
   API shef.insync (с запросом и ответом), вторую — агент или кнопка
   (итог). Это один сбой, а не два.
2. **Агент**: `/bitrix/admin/agent_list.php`, модуль `shef.currency`,
   строка `\Shef\Currency\Sync\Agent::process([]);` — активен? когда
   следующий запуск? Агенты на хитах — портал без посетителей их не
   запускает, нужен cron (`shef-new-agent`, «Cron вместо агента»).
3. **Порог**: курс сдвинулся меньше порога — не записан, и это не сбой.
   Сравните курс за единицу у банка и на портале.
4. Нет в журнале ничего, а курса нет — валюты нет на портале, она
   базовая или банк её не котирует (нет в ответе банка — её курса и нет).

## Запросить руками

Кнопкой — страница курсов, «[SH] Запросить курсы валют» → «На сегодня» или
«На завтра». Нужно право «W» на модуль «Валюты». После запроса над списком
сообщение: записано; записывать нечего (порог отсеял всё или валют портала
нет в ответе банка); не записано (причина — в журнале).

Из консоли: «Командная PHP-строка» административной части
(`/bitrix/admin/php_command_line.php`) либо скрипт `php` с прологом ядра
на сервере портала:

```php
\Bitrix\Main\Loader::includeModule('shef.currency');

// Как агент, с отладкой: ошибки — ещё и на экран.
\Shef\Currency\Sync\Agent::process(['debug' => 'Y']);

// На конкретную дату, итог — в Result.
$result = \Shef\Currency\Sync\Agent::getInstance()->sync(
	(new \Bitrix\Main\Type\Date())->add('1D')
);
var_dump($result->isSuccess(), $result->getErrorMessages(), $result->getData());
```

`getData()['written']` — коды записанных валют. Пустой при успехе — всё
отсеял порог, либо валют портала нет в ответе банка. Что было бы
записано, не записывая, — `Agent::getInstance()->preview($date)`, данные
`plan`.

## Чего не делать

* Не ставить базовой валютой не BYN «на время» — модуль перестанет писать.
  Что при переключении базовой валюты происходит с уже записанными
  курсами, модуль не определяет — это поведение ядра, проверять на стенде.
* Не править курс руками и ждать, что агент его не тронет: курс на дату
  агент обновит, если сдвиг от вашего значения не меньше порога.
* Не заводить второй агент на тот же класс: строка агента одна, её ищут по
  имени — модуль и страница настроек.
* Не менять адрес сервиса на `api.nbrb.by` без правки разбора: там JSON, а
  `Rates::parseXml()` разбирает XML `XmlExRates.aspx`.
